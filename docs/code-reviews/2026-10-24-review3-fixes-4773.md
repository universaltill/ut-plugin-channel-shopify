# Changes after the third independent review (ut-docs#4773)

Reviewer: Fable 5.1 (independent). Builder: Sonnet 5.5. Version 0.1.1.
Nothing here was run against a real Shopify store; Shopify names remain the
unverified ones listed in the README.

| # | Severity | Finding | Resolution |
|---|---|---|---|
| M1 | Medium | `budget.go` and the README claimed the host paces every request by its `cost_hint`; ut-cloud `egress.go` stores it and never reads it (retry back-off only, six attempts, then dead-letter) | Comments, README and CLAUDE.md rewritten: budgets are in-plugin accounting, wall time is requests x latency, a ut-cloud card tracks host pacing. Behaviour kept. New test `TestAThrottledTickEndsSafelyAndTheSweepResumes`: a fully throttled tick errors, moves no cursor, submits nothing, and the sweep later finishes with all orders |
| M2 | Medium | At most 4 orders per tick; 1,000 orders take about 62 h | `orderPage`/`maxOrderPages` moved to `budget.go` with a comment; README dev-store row (read `actualQueryCost`, then raise the page constants and lower the cost hint) and a note that a big shop's first sweep is slow (lag, no loss). No adaptive page size: Shopify's real cost is unknown |
| M3 | Medium | One `fulfillmentCreate` for all fulfilment orders; Shopify needs one location per fulfillment | Grouped by `assignedLocation` (`fFOLocation`, in the from-memory block), one create per group; a refused group does not stop the others; the op is acked `rejected_by_channel` (non-retryable) and a retry re-reads and sends only what is still open; transport errors stop and are retryable. Fake shop now enforces the one-location rule. Tests: `...MultiLocationOrderIsOneCreatePerLocation`, `...FailedLocationGroup...` |
| L4 | Low | A wrong stock field name dead-letters every `stock.set` | Hard "do not queue real stock ops" note above the verify table; `outbox.graphql_error` log code with Shopify's error code; test `...GraphQLSchemaErrorOnStockSetDeadLettersWithAStableLogCode` pins one request, non-retryable ack, stable code |
| L5 | Low | Fetch refused more than 100 ids; the host sends up to 250 | `maxFetchIDs = 250`; the fetch reads what its budget allows and defers the rest to the tick (`fetch.deferred_to_tick`). Test `TestFetchAccepts250Ids...` |
| L6 | Low | The wasm was not reproducible | `-trimpath` in `scripts/build.sh`; two builds gave the same sha256. `bin/` and `dist/` are git-ignored and stay uncommitted |
| L7 | Low | "~40 mutations" is not evidenced in the repo | Review record wording reduced to what the tests show (round-2 record) |
