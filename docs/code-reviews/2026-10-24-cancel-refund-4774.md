## Decisions

1. Refund sends the op id as BOTH Shopify's `@idempotent` key (ADR-0169 says it
   is mandatory on refund mutations) and the host's `Idempotency-Key`, which
   makes a host re-send safe if the directive works as documented. The brief
   called the header a host-only signal; if the reviewer prefers, drop the
   header argument in `refundCreate` (one token) and keep the directive: the read
   alone then carries exactly-once.
2. Cancel carries no key: a re-sent cancel is a user error that would hide the
   first one's success.
3. The ceiling compares the larger of `amountSet` and the transactions' sum, so
   a case where Shopify caps the cash below the line value can be refused when
   the cloud ceiling is the lower number. Chosen as the safe side.
4. Stable code for a fulfilled order is `order_fulfilled` (the ack has a code
   only), not the generic `rejected_by_channel`.
5. Cancel uses `refund: true`: the cloud's confirmation marks every unit
   refunded.
