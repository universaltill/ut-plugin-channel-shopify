# Review record: declare `items: both` (ut-docs#4773)

Branch `fix/items-both`, manifest 0.2.0 to 0.2.1. Reviewer Opus 5.5, builder Sonnet 5.5.

## Why

The cloud's outbound catalogue sweep (ut-cloud `internal/channelsync/outbound.go`
`SweepOutbound`) queues `listing.upsert` only when the manifest declares `items`
as `push` or `both`. With `items: "pull"` the variant-price push the adapter
implements (a Universal Till price edit reaching Shopify, ADR-0169 MVP
criterion 6) was unreachable. The sweep covers only a connection's own
ChannelListing rows: products the import created, and items an owner publishes
from Universal Till (those have no external id, so their op is a create).

## What changed

- `manifest.json`: `items: both`; version 0.2.1 (version-bump guard).
- `src/app/outbox.go` `listingUpsert`: no external id = create = non-retryable
  `create_not_supported` before any request (logged `listing.create_not_supported`);
  extra payload fields beyond `variants` are ignored without error and counted
  once per ask as `listing.fields_ignored` (count only, no field values, no PII);
  price push unchanged. `src/app/budget.go`: per-ask flag for the once-per-ask log.
- `listing.unpublish` and everything else: unchanged (`unsupported_op`, no mutation).
- `scripts/validate.sh` pins `items == both` with the reason in a comment.
- Tests (`src/app/outbox_test.go`): other fields ignored + price pushed + log once per
  ask (and again on the next ask); creates (several malformed bodies) refused, zero
  requests. `conformance/shopify_test.go`: `createRefusal` check with a broken
  self-test adapter that creates blindly; suite.go untouched (stays a copy of the demo suite).
- README (outbox row, Capabilities, new "Verify first on the dev store" row) and
  CLAUDE.md state the truth.

## What the cloud does with a create refusal (read in ut-cloud, not run)

`Outbox.Ack` (`channelsync/outbox.go`): a non-retryable error goes straight to
`deadLetter(..., ambiguous = Retryable = false)`. The op ends `dead_letter`, the
listing's `last_pushed_hash` becomes `dead:<hash>`, and the sweep skips that hash
(`outbound.go` `hash == dead+hash`), so it does not retry forever and later edits
(a new hash) are queued normally. **No Review entry is raised**: `raiseCreateEntry`
(`create_failed` / `create_unconfirmed`) runs only for an AMBIGUOUS create
(retryable, exhausted, or unconfirmed). So the owner sees a dead-lettered
operation, not a Review item; each further edit of that item queues another
create that is refused again.
