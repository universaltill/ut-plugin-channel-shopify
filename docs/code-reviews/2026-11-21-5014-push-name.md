## What changed

- `manifest.json`: `push_fields ["price","name"]`, version 0.5.0.
- `src/app/outbox.go`: one read of the variant's product (title, status,
  `updatedAt`, `variantsCount`), then every field is decided from it:
  `changed` absent = price only; empty = ack, no request; only fields in
  `changed` are written; skip when Shopify already has the value or differs
  from `was` and `updatedAt` > `at`; title only on single-variant products
  (skips counted, one `listing.name_skipped_multi_variant` log per ask);
  title 1..255 characters or `invalid_payload` before any request; title and
  status in one `productUpdate`; a refused update never dead-letters a written
  price; `listing.unpublish` -> DRAFT (ACTIVE products of a single variant
  only); reactivation only with `changed.active`; ARCHIVED never touched.
- `src/app/stamp.go`: RFC 3339 comparison without `time` (denied in `src/`).
- `internal/fakeshop`: title/status in the variant read, `productUpdate`
  title/status, `SetTitle`, `SetStatus`, `Title`.
- Ignored-fields list: name and status are no longer ignored.

## Decisions to check

- Status is also limited to single-variant products (the design says it for the
  name only): unpublishing one variant's item must not hide its siblings.
- `variantsCount { count }`, `status`, `title` in `productUpdate` are from
  memory: README verify row; run on the dev store before approving the release.
- A name-only or status-only `productUpdate` refused by Shopify is
  `rejected_by_channel` (not a silent ack, which would move the cloud baseline
  to a value Shopify never took).
- An invalid title refuses the whole op (the price of that op is not pushed).
