**S1 (important, unverified) `src/app/queries.go:62-67,195,202` requested-cost hints not re-derived.**
`productFields` gained `media(first: 10)` per product and `variantFields` gained `media(first: 1)` per variant, but `qProducts.Cost` (700) and `qProductsByID.Cost` (880) are unchanged, and `productPage=4`, `variantPage=50`, `productsPerRead=5` were sized to keep the REQUESTED cost under Shopify's 1,000 limit. By Shopify's rule (connection = 2 + first x child cost) the extra per product at 50 variants is about 12 + 50x3 = ~160, so 4 products add ~650 and 5 products add ~800, which would put both queries over 1000 (MAX_COST_EXCEEDED on every large-variant product import, and the hint is also the budget input at `catalogue.go:236`). The README evidence (README row "Verified 2026-11-27") measured 10 products x 5 variants (requested 102), not production page sizes, and I cannot reproduce 102 from the formula, so my estimate may be too high. Failure scenario: a shop with products of ~50 variants: Products query returns a cost error, import stalls with no listings.
Check (read-only, dev store): run `Products` with `first:4, vfirst:50` and `ProductsByID` with 5 ids and `vfirst:50`; read `extensions.cost.requestedQueryCost`. If any exceeds 1000, lower `productPage`/`productsPerRead` or `variantPage`, and set `Cost:` to the measured value. This can be done on a dev store even with small products, because requested cost depends on `first`, not on actual data.
